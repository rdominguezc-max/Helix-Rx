# UX / UI Design Guide

**Proyecto:** helix

**Versión:** 0.1

**Estado:** Draft

---

# Objetivo

Diseñar una experiencia simple, intuitiva y accesible que permita utilizar helix sin capacitación previa, independientemente de la edad o conocimientos tecnológicos del usuario.

---

# Filosofía

La salud ya es suficientemente complicada.

La aplicación no debe serlo.

Cada pantalla deberá tener un único objetivo.

El usuario nunca deberá preguntarse qué hacer.

---

# Principios de Diseño

* Menos es más.
* Máximo tres toques para cualquier acción importante.
* Información progresiva.
* Botones grandes.
* Lenguaje sencillo.
* Diseño consistente.
* Accesibilidad como prioridad.

---

# Usuarios Objetivo

La aplicación deberá ser fácil de utilizar para:

* Adolescentes.
* Adultos.
* Adultos mayores.
* Personas con poca experiencia tecnológica.
* Personas con discapacidad visual leve.

---

# Mobile First

La interfaz deberá diseñarse primero para teléfonos móviles.

Posteriormente adaptarse a:

* Tablet.
* Laptop.
* Desktop.

---

# Navegación Principal

La barra inferior contendrá únicamente cinco opciones:

* Inicio
* Medicamentos
* Agenda
* Mi Salud
* Perfil

---

# Pantalla Principal

Debe mostrar únicamente:

* Próximo medicamento.
* HELIX Score.
* Semáforo de riesgo.
* Próxima consulta.
* Acciones rápidas.

---

# Acciones Rápidas

Siempre visibles:

* Tomé mi medicamento.
* Posponer.
* Omitir.
* Registrar crisis.
* Contactar médico.
* Pedir ayuda.

---

# Colores

## Primarios

* Azul.
* Verde.

## Secundarios

* Gris claro.
* Blanco.

## Alertas

* Amarillo.
* Naranja.
* Rojo.

---

# Fondo

Utilizar fondos claros con patrones muy discretos inspirados en conexiones neuronales y señales eléctricas.

El fondo nunca deberá competir con el contenido.

---

# Tipografía

Sans Serif.

Muy legible.

Escalable.

Configurable por el usuario.

---

# Botones

Altura mínima:

48 px.

Siempre con:

* Icono.
* Texto.

---

# Iconografía

Simple.

Universal.

Consistente.

Nunca depender únicamente del icono para comunicar una acción importante.

---

# Accesibilidad

Cumplir WCAG AA.

* Buen contraste.
* Compatible con lectores de pantalla.
* Navegación por teclado.
* Áreas táctiles amplias.

---

# Animaciones

Suaves.

Duración máxima:

300 ms.

Nunca deberán retrasar la interacción del usuario.

---

# Formularios

* Pocos campos por pantalla.
* Guardado automático.
* Validaciones claras.
* Autocompletado cuando sea posible.

---

# Mensajes

Utilizar lenguaje sencillo.

Ejemplo:

Incorrecto:

"No fue posible completar la operación."

Correcto:

"No pudimos guardar tu medicamento. Inténtalo nuevamente."

---

# Gamificación Responsable

Utilizar únicamente elementos que fomenten hábitos saludables.

Ejemplos:

* Rachas.
* Objetivos.
* Logros.
* Reconocimientos.

Nunca utilizar castigos o elementos que generen ansiedad.

---

# HELIX Score

Siempre mostrar:

* Valor.
* Color.
* Tendencia.
* Explicación sencilla.
* Botón "¿Cómo puedo mejorarlo?"

---

# Semáforo de Riesgo

Verde.

Amarillo.

Rojo.

Cada nivel deberá explicar claramente:

* Qué significa.
* Qué debe hacer el paciente.

---

# Modo Demo

Disponible desde la pantalla inicial.

Sin necesidad de registro.

Datos completamente ficticios.

Reinicio automático.

---

# Multiidioma

Toda la interfaz deberá poder traducirse sin modificar el código.

---

# Experiencia del Médico

Priorizar productividad.

* Menos clics.
* Más información.
* Dashboards claros.
* Filtros rápidos.

---

# Experiencia del Paciente

Priorizar:

* Simplicidad.
* Tranquilidad.
* Seguimiento.
* Motivación.

Nunca generar miedo innecesario.

---

# Personalidad Visual

La aplicación deberá transmitir:

* Confianza.
* Cercanía.
* Esperanza.
* Innovación.
* Profesionalismo.

No deberá parecer un sistema hospitalario antiguo.

---

# Definición Final

Si un adulto mayor puede utilizar helix durante cinco minutos sin ayuda y comprender cómo confirmar un medicamento, consultar su próxima cita y solicitar apoyo, el diseño habrá cumplido su objetivo.
